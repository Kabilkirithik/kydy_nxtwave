 complete, practical backend design for your animated‑slides AI tutoring system, written for immediate implementation. Architecture — single sentence
A microservice backend that accepts teach me {topic} prompts → orchestrates LLM + RAG + agents to produce a validated LessonTimeline JSON and sanitized SVG assets (hosted on CDN) that the frontend animates as parametric slides.

Core components
API Gateway / Ingress

POST /api/v1/sessions — create lesson session from prompt.

GET /api/v1/sessions/{id} — fetch saved timeline & assets.

Auth (JWT), rate-limits, request validation.

Orchestrator (Crew / agent runner)

Creates Agents and Tasks: parse_agent, retrieve_agent, timeline_agent, svg_agent, validator_agent.

Drives task execution and error handling (sync/async via task queue).

LLM Layer

At least two LLM roles:

LLM_small: classification/parse tasks (cheap, low-latency).

LLM_author: timeline composition and explanations.

Optional LLM_svg or a fine-tuned model for text→SVG when parametric templates aren’t enough.

RAG / Vector DB

Stores embeddings for:

primitive templates/metadata (render contracts)

domain reference docs, example timelines

Retriever returns top-K docs to feed LLM prompts.

Primitive Store

Metadata store mapping domain:subdomain → allowed primitives, param schemas, fallback templates.

SVG Generation Service

Two tiers:

Parametric generator (primary): programmatic templates that take parameters → deterministic SVG.

Model-based generator (fallback): LLM or trained model returning <svg> blocks (sanitize strictly).

CDN/S3 hosting for final asset URLs.

Sanitizer & Validator

lxml parser allowlist tags/attributes, strip scripts/on* handlers, require width/height.

Timeline validator enforces schema, duration bounds, primitives allowed.

Session & Persistence

Store sessions/timelines (Postgres / DynamoDB) and caching in Redis.

Asset metadata in DB; assets on S3 + CDN.

Queue & Workers

Long-running generation (complex SVGs) run as background jobs (RabbitMQ/SQS + worker pool).

WebSocket/SSE for progress updates to frontend.

Monitoring & Observability

Metrics (Prometheus), logs (ELK), tracing (OpenTelemetry).

LLM token/cost metrics.

Orchestration flow (step‑by‑step)
Client POST /api/v1/sessions with { prompt: "teach me Ohm's law" }.

API validates request and enqueues a sync orchestration job (or returns session with status pending).

parse_agent (LLM_small): returns strict JSON {domain, subdomain, topic, audience, duration_min, objectives}.

retrieve_agent: queries PrimitiveStore & RAG for allowed primitives and reference docs.

timeline_agent (LLM_author): given topic + allowed primitives + references → generates LessonTimeline JSON (strict schema).

Validate timeline with validator_agent. If invalid, return validation_failed + errors.

For each svg layer without assetUrl:

If primitive is parametric → call Parametric Renderer (fast) → returns SVG → sanitize → upload CDN → attach assetUrl.

Else call svg_agent (LLM_svg) → get <svg> block → sanitize → upload CDN → attach assetUrl.

Re-validate timeline. If passes, persist session and return session_id + timeline.

Frontend fetches timeline and animates.

Agents & responsibilities
parse_agent: cleanly extract intent + constraints; ALWAYS return only JSON.

retrieve_agent: RAG + primitive metadata fetch.

timeline_agent: produce LessonTimeline JSON using only allowed primitives (strict constraints: max segments, durations).

svg_agent: produce or call renderer for SVG assets; return sanitized asset_url.

validator_agent: run schema checks and primitive contract checks.

Each Task should include expected_output for CI/runtime assertions.

SVG generation: recommended approach
Parametric-first

Build a library of small templates (battery, resistor, graphs, arrow, particle stream).

Templates accept parameters (width,height,stroke,color,counts) → return SVG string.

Pros: deterministic, safe, tiny, easy to animate with CSS/SVG <animate>.

LLM / model fallback

Use a text→SVG model or instruct LLM to return <svg>...</svg> blocks.

Very strict system prompts; post-LLM sanitize with allowlist.

Use only when parametric templates can’t represent required visual.

Sanitization rules

Allowed tags: svg,g,rect,circle,ellipse,line,path,text,defs,use,animate,animateTransform.

Remove <script>, on* attributes; disallow external href/xlink:href to untrusted hosts.

Require width and height at root.

Validation & testing
Use JSON Schema for LessonTimeline; validate at runtime with jsonschema.

Every Task gets expected_output for unit tests.

Unit tests: mock ollm.call, cdn_tool.run, and PrimitiveStore to produce deterministic outputs.

E2E tests: parametric generator only (no LLM).

Persistence & caching
DB: Postgres for sessions, metadata; store asset metadata.

Blob: S3 + CloudFront CDN for SVGs.

Cache: Redis for session lookups and reclaiming previously generated SVGs.

Index: vector DB (Pinecone/Weaviate/Milvus) for RAG.

Security & privacy
Remove PII from prompts before logging.

Rate-limit and authenticate requests.

Sanitize all generated assets (no script tags, no external resources).

Content filtering on LLM output for policy violations.

Scaling / cost strategies
Use cheap models for classification and expensive ones only for authoring.

Parametric SVGs reduce LLM usage and cost.

Cache timelines & SVGs aggressively (hash prompt → reuse).

Offload heavy tasks to workers and return immediate session id with progress.

Observability & metrics
Track: agent latency, LLM token usage, validation failures, svg sanitization failures.

Tracing across agent calls (OpenTelemetry).

Alerts on error rates, slow LLM responses, high token consumption.
